Warm-up — Python list vs array

Plain Python: [1,2,3] * 2 → ?   NumPy: np.array([1,2,3]) * 2 → ?   Predict both, then explain the difference in one sentence.
ANSWER
[1,2,3] * 2                  # [1, 2, 3, 1, 2, 3]   (repeat)
np.array([1,2,3]) * 2        # [2, 4, 6]            (element-wise)
Critical: Same syntax, different meaning. Python list = container of objects. NumPy array = math object. The whole point of switching libs.

Why arrays?

  • 1,000,000 numbers. Multiply each by 2.
  • Python list + for loop $\Rightarrow$ slow. Seconds.
  • NumPy: a * 2. One line. ~50× faster.
  • Same idea powers GPU neural net training.

Loops expensive. Arrays cheap. Think in arrays.

What is NumPy?

  • N-dimensional array library for Python.
  • Foundation under pandas, scikit-learn, PyTorch, TensorFlow.
  • Written in C → fast loops without writing C.

Normalize each column

Dataset has 5 students × 3 subjects. Subtract each subject's mean from every student's score, so every column has mean 0. Will data - data.mean() work? Why not?
GIVEN
data = np.array([[80, 70, 60], [85, 65, 75], [90, 80, 70], [60, 75, 85], [70, 90, 80]])
Think: data.mean() = scalar. data.mean(axis=0) = shape (3,). Which one broadcasts the way you want? What shape result do you need?
SOLUTION
col_means = data.mean(axis=0)   # shape (3,) — one per subject
centered  = data - col_means     # broadcasts down rows

centered.mean(axis=0)            # ≈ [0, 0, 0] ✓

Find the outliers

Lab measured 20 sensor readings. Anything more than 2 standard deviations from the mean is suspect. Find: how many outliers, their indices, and replace them with the median.
GIVEN
rng = np.random.default_rng(0); x = rng.normal(50, 5, size=20); x[3] = 90; x[15] = 10
Think: Mask = boolean array. mask.sum() counts True. np.where(mask) gives indices. x[mask] = value assigns in place.
SOLUTION
mean, std = x.mean(), x.std()
mask = np.abs(x - mean) > 2 * std

n_out   = mask.sum()
idx_out = np.where(mask)[0]
x[mask] = np.median(x)            # replace in place
Critical: Why use median not mean for replacement? (Outliers pull mean. Median is robust.)

Why did my array change?

You write a function: def normalize(x): x -= x.mean(); return x. Caller passes a. After return — caller's a is also modified! Explain in one sentence. Fix it without renaming the function.
SOLUTION
def normalize(x):
    x = x - x.mean()        # rebind to new array
    return x

# or explicit copy at entry
def normalize(x):
    x = x.copy()
    x -= x.mean()
    return x
Critical: x -= ... is in-place. Mutates whatever object x references — including caller's. NumPy makes this trap easy to step in.

Day 1 pitfalls

  • view vs copy — slices are views. Mutating slice mutates original. Use .copy() when scared.
  • int vs float — np.zeros(3) is float. np.zeros(3, dtype=int) if you need int.
  • shape mismatch — (3,) ≠ (3, 1). Broadcasting cares.
  • NaN poisons — np.nan + x = nan. Use np.nanmean, etc.
  • @ vs * — matmul vs element-wise. Different operators.

Most bugs = shape bug. print(a.shape) is your friend.

100 students. 5 exams. Score matrix shape (100, 5). Without any for loop, answer: (1) mean per exam, (2) top student's total, (3) how many students passed all 5 (passing = ≥ 50), (4) rank of student #7 by total score.

loc vs iloc — which one?

Given a DataFrame with index [10, 20, 30, 40, 50] and columns ["a","b","c"]. Predict each result before running it:
① df.loc[20]   ② df.iloc[20]   ③ df.loc[10:30]   ④ df.iloc[10:30]
Think: loc = labels (inclusive end!). iloc = positions (exclusive end like Python). Indexes don't have to be 0,1,2.
SOLUTION
① df.loc[20]      → row with label 20 (the 2nd row)
② df.iloc[20]     → IndexError (only 5 rows!)
③ df.loc[10:30]   → rows labeled 10, 20, 30 (3 rows, inclusive)
④ df.iloc[10:30]  → empty DataFrame (positions 10..29 don't exist)
Critical: Most pandas bugs come from confusing these two. Read your own indices before slicing.

scikit-learn

split → fit → predict → score.
The one pattern that fits every model.

What is supervised ML?

  • You have X (features) and y (labels).
  • Model learns the mapping f(X) ≈ y from examples.
  • Then predicts y for new X it never saw.

Math view:

$$\hat{y} = f_\theta(X) \quad \text{learn } \theta \text{ to minimize loss}(y, \hat{y})$$

Classification = y is a category (survived / didn't). Regression = y is a number (house price).

What "learning" actually does

Model = formula with unknown parameters. Training = adjust parameters until predictions match labels.

Input X
(age, fare, sex…)
→
Parameters θ
weights, splits, …
→
Output ŷ
prediction

$$\text{loss} = \text{distance}(y, \hat{y}) \quad \Rightarrow \quad \theta \leftarrow \theta - \nabla_\theta \text{loss}$$

For 1000s of examples: predict → measure error → nudge parameters → repeat.
That loop is training. Every model does this — just different shapes of θ.

LogReg θ = weights vector. Tree θ = split rules. Neural net θ = millions of weights. Same idea.

Classify the problem itself

Decide: classification, regression, or unsupervised?
  • ① Predict tomorrow's stock price.
  • ② Detect spam email vs not-spam.
  • ③ Group customers into similar segments.
  • ④ Predict house price.
  • ⑤ Recognize digit (0–9) in image.
ANSWERS
  • ① regression (continuous)
  • ② classification (2-class)
  • ③ unsupervised — no labels
  • ④ regression
  • ⑤ classification (10-class)
Critical: Wrong problem type = wrong metric, wrong model. Target column dtype usually tells you the type.

precision = TP / (TP + FP) = 120/170 = 0.71
recall    = TP / (TP + FN) = 120/200 = 0.60
F1        = 2·P·R / (P+R)  = 0.65
Critical: FP = real email in spam folder (loses your job). FN = spam in inbox (annoying). Different users want different tradeoffs. Always ask: which error costs more?

Metric 3 — precision, recall, F1

$$\text{precision} = \frac{TP}{TP+FP}$$

of what you flagged, how much was real.

$$\text{recall} = \frac{TP}{TP+FN}$$

of real positives, how many you caught.

$$F_1 = 2 \cdot \frac{P \cdot R}{P + R}$$

harmonic mean. Balanced single number.

from sklearn.metrics import classification_report

print(classification_report(y_test, y_pred))

#               precision  recall  f1   support
#       0          0.86     0.90  0.88     100
#       1          0.89     0.85  0.87     100
#
#  accuracy                       0.88     200

When in doubt, report F1. Single number. Tells you both sides.

Two models, which wins?

Same test set. Model A: accuracy 0.88, F1 0.45. Model B: accuracy 0.82, F1 0.71. Which would you ship for fraud detection? For predicting customer satisfaction (mostly happy)?
Think: High accuracy + low F1 = model trivially predicts majority class. F1 reflects minority-class performance.
DECISION
  • Fraud (imbalanced): ship Model B. Higher F1 = better at catching real fraud, even with lower accuracy.
  • Satisfaction (balanced-ish): Model A is fine; accuracy is honest here.
Critical: Metric depends on cost of errors and class balance. Pick the metric before you train, not after.

Fix it — bias vs variance

Underfit (high bias)

  • Use stronger model (RF > LogReg).
  • Add features. Feature engineer.
  • Reduce regularization (LogReg C ↑).
  • Train longer / increase tree depth.

Overfit (high variance)

  • Get more data.
  • Simpler model (lower max_depth).
  • More regularization (LogReg C ↓).
  • Remove leaky / redundant features.
  • Use cross-validation to detect honestly.
Trap: if test > train — you almost certainly leaked. Test data crept into training. Re-check your split.

Day 3 pitfalls

  • Data leakage — fitting any transformer on test data. Fit on train, apply to test. Never the reverse.
  • Strings in X — sklearn errors. Encode first.
  • NaN in X — sklearn errors. Fill first.
  • No random_state — your "improvement" was just luck. Always seed.
  • Accuracy on imbalanced — lies. Use F1.
  • Score on train — meaningless. Score on test.
