If you know NumPy, you already know 90% of PyTorch tensor syntax. The new bits are GPU + grad.

GPU + grad in code

import torch

# 1. create on CPU
a = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
print(a.shape)        # torch.Size([2, 2])
print(a.dtype)        # torch.float32

# 2. move to GPU (if available)
device = 'cuda' if torch.cuda.is_available() else 'cpu'
a = a.to(device)

# 3. track gradients (for training)
w = torch.randn(3, 2, requires_grad=True)

# 4. NumPy ↔ PyTorch conversion
np_arr = a.cpu().numpy()         # to NumPy (must be on CPU first)
back   = torch.from_numpy(np_arr) # back to tensor
  • device string: 'cuda' or 'cpu'. Always check cuda.is_available().
  • requires_grad: tensor remembers all ops, builds graph for backward pass.
  • Going to NumPy: first .cpu(), then .numpy(). GPU tensors can't convert directly.

Input shapes — vectors and batches

Models eat batches of tensors. The first dimension is always batch size.

data typeshapeexample
tabular row(batch, n_features)(32, 4) — 32 Titanic rows, 4 features
flat image (MNIST)(batch, 784)(32, 784) — 28×28 flattened
RGB image(batch, 3, H, W)(32, 3, 224, 224)
label vector(batch,)(32,) — class id per row
# flatten an image batch
images.shape             # (32, 1, 28, 28)
images.view(32, -1)         # (32, 784)
# or use nn.Flatten() inside the model

Every shape mismatch error traces back to a wrong batch or feature dimension. Always print .shape when stuck.

Linear layer — matmul + learnable weights

import torch.nn as nn

layer = nn.Linear(3, 2)   # in=3, out=2
x = torch.randn(5, 3)     # batch of 5, 3 features each
y = layer(x)              # shape: (5, 2)

# inside, layer holds:
layer.weight              # shape (2, 3) — learned
layer.bias                # shape (2,)   — learned

Math: $y = xW^T + b$.

  • in_features: how many numbers come in per row.
  • out_features: how many come out.
  • Weights start random. Training adjusts them.

Activation — ReLU adds non-linearity

Stack two Linear layers without activation $\Rightarrow$ still just one big linear function. Useless. Activation makes the network learn curves.

relu = nn.ReLU()

x = torch.tensor([-2.0, -0.5, 0.0, 1.0, 3.0])
relu(x)
# tensor([0., 0., 0., 1., 3.])

Rule: $\text{ReLU}(x) = \max(0, x)$.

  • Negatives → 0. Positives pass through.
  • Cheap (one max op) and avoids vanishing gradients.
  • Standard in 2025. Other options: nn.GELU, nn.SiLU, nn.Tanh.
ReLU(x) = max(0, x)

  • Input: 784 = 28×28 pixels flattened.
  • Hidden: 128 = arbitrary choice. Bigger = more capacity.
  • Output: 10 = number of digit classes.
  • No activation after the final layer for classification — loss handles it.

nn.Sequential — stack layers in order

import torch.nn as nn

model = nn.Sequential(
    nn.Flatten(),               # (B, 1, 28, 28) → (B, 784)
    nn.Linear(784, 128),
    nn.ReLU(),
    nn.Linear(128, 10),
)

# forward pass — input flows top to bottom
x = torch.randn(32, 1, 28, 28)
output = model(x)               # shape: (32, 10)

print(model)                  # pretty-prints the architecture
  • nn.Flatten: reshape image batches into vectors. Replaces .view(-1, 784).
  • Each layer's output = next layer's input. Sizes must match.
  • Calling model(x) runs forward automatically. Don't call model.forward(x) directly.

How many parameters?

Each Linear layer ships weights + bias. Count grows with width.

layerweightsbiastotal
nn.Linear(784, 128)784 × 128 = 100,352128100,480

# count params programmatically
total = sum(p.numel() for p in model.parameters())
trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
  • Activation layers (ReLU) have zero parameters.
  • Most params live in early Linear layers when input is wide.
  • ResNet18 ≈ 11 million params. GPT-3 ≈ 175 billion. Same arithmetic, different scale.
