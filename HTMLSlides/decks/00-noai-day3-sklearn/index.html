The one pattern that fits every model.

What is supervised ML?

  • You have X (features) and y (labels).
  • Model learns the mapping f(X) ≈ y from examples.
  • Then predicts y for new X it never saw.

Math view:

$$\hat{y} = f_\theta(X) \quad \text{learn } \theta \text{ to minimize loss}(y, \hat{y})$$

Classification = y is a category (survived / didn't). Regression = y is a number (house price).

What "learning" actually does

Model = formula with unknown parameters. Training = adjust parameters until predictions match labels.

Input X
(age, fare, sex…)
→
Parameters θ
weights, splits, …
→
Output ŷ
prediction

$$\text{loss} = \text{distance}(y, \hat{y}) \quad \Rightarrow \quad \theta \leftarrow \theta - \nabla_\theta \text{loss}$$

For 1000s of examples: predict → measure error → nudge parameters → repeat.
That loop is training. Every model does this — just different shapes of θ.

LogReg θ = weights vector. Tree θ = split rules. Neural net θ = millions of weights. Same idea.

Classify the problem itself

Decide: classification, regression, or unsupervised?
  • ① Predict tomorrow's stock price.
  • ② Detect spam email vs not-spam.
  • ③ Group customers into similar segments.
  • ④ Predict house price.
  • ⑤ Recognize digit (0–9) in image.
ANSWERS
  • ① regression (continuous)
  • ② classification (2-class)
  • ③ unsupervised — no labels
  • ④ regression
  • ⑤ classification (10-class)
Critical: Wrong problem type = wrong metric, wrong model. Target column dtype usually tells you the type.

Why split?

Score on training data = the model memorized it. Useless. Score on data it never saw = the real number.

TRAIN — 80%
TEST 20%

The imbalanced split

Fraud dataset: 10,000 transactions, only 50 fraud (0.5%). You train_test_split(test_size=0.2) with no stratify. What's the worst-case test set composition? How does stratify=y fix this?
Think: 50 frauds in 10000. Test = 2000 rows. By chance, test could end up with 0 frauds. Then "accuracy = 100%" by predicting "not fraud" for everyone.
SOLUTION

y_te.mean()   # ≈ 0.005 — matches overall ratio
Critical: For imbalanced classification — stratify=y is not optional. And accuracy alone still lies. Switch to F1 / recall.

Model 1 — Logistic Regression

    max_iter=1000

model.coef_         # feature weights
model.intercept_
  • Linear boundary. Output = probability via sigmoid $\sigma(z) = \frac{1}{1+e^{-z}}$.
  • Fast baseline. Run first to set the floor.
  • Interpretable — coef_ tells you feature importance.
  • If LogReg already strong → problem is easy / linear.
Default max_iter is low. Bump to 1000 to silence convergence warnings.

Read the model's mind

After fitting LogReg on Titanic, model.coef_ shows: Sex_female = +2.5, Pclass = −0.9, Age = −0.03, Fare = +0.002. What does each tell you? Which feature does the model think matters least?
Think: Positive coef = increases survival probability. Negative = decreases. Magnitude only comparable if features scaled the same.
INTERPRETATION
  • Sex_female +2.5 — being female greatly boosts survival.
  • Pclass −0.9 — higher class number (3rd class) hurts.
  • Age −0.03 — slight: older = slight drop.
  • Fare +0.002 — looks weak, but Fare range is 0–512, so total contribution is real.
Critical: Don't compare raw coefs across features with different scales. Scale your X first, or compare coef × std(feature).

How a decision tree thinks

Each node asks one yes/no question. Path from root to leaf = a rule.

  • Tree picks splits that separate classes best — Gini / entropy.
  • Deeper tree = more rules = can memorize training set.
  • Overfit prone — one tree often too greedy.
  • Solution: many trees vote → Random Forest.

Random Forest = many trees vote

Each tree trained on a random subset. Final prediction = majority vote.

Tree 1 → A
Tree 2 → B
Tree 3 → A
→
Vote
A · 2/3
final prediction

One tree = opinion. Many trees = wisdom of crowd. Errors cancel.

Feature scaling — when it matters

from sklearn.preprocessing import StandardScaler, MinMaxScaler

scaler = StandardScaler()
X_tr_scaled = scaler.fit_transform(X_tr)
X_te_scaled = scaler.transform(X_te)
# mean ≈ 0, std ≈ 1

# or MinMax to [0, 1]
mm = MinMaxScaler()
X_tr_mm = mm.fit_transform(X_tr)
  • Needs scaling: LogReg, SVM, KNN, neural nets.
  • Doesn't care: trees, RandomForest, GBM.
  • Critical: fit ONLY on train. Then transform test. Otherwise = data leak.
Common bug: scaler.fit_transform(X) before splitting. Test set then influences scaler statistics. Always: split → fit on train → transform both.

Why my KNN crashed

Features: Age (0–80), Fare (0–500), FamilySize (0–10). You train KNN with k=5, get 0.62. After scaling features, accuracy jumps to 0.81. Explain why in one sentence.
EXPLANATION
# KNN uses Euclidean distance:
# d² = (ΔAge)² + (ΔFare)² + (ΔFam)²
#
# Fare's range (500) dominates the sum.
# Effectively only Fare decides neighbors. Age + FamilySize ignored.

scaler = StandardScaler()
X_tr_s = scaler.fit_transform(X_tr)
X_te_s = scaler.transform(X_te)
KNeighborsClassifier(5).fit(X_tr_s, y_tr).score(X_te_s, y_te)
Critical: Same problem with neural nets, gradient descent, SVM. Whenever distance / dot products appear → scale or regret.

The 99% trap

Disease test: 990 healthy, 10 sick. Model predicts "healthy" for everyone. Accuracy = 99%. Why is this model useless? What metric exposes it?
Think: Accuracy weights all correct predictions equally. It doesn't care which class you got right.
SOLUTION
y_pred = np.zeros(1000)               # predict all healthy

accuracy_score(y_true, y_pred)     # 0.99 — fake win

from sklearn.metrics import recall_score, f1_score
recall_score(y_true, y_pred)       # 0.0 — caught no sick people!
f1_score(y_true, y_pred)           # 0.0
Critical: For imbalanced classes — recall on the rare class is what matters. A doctor who diagnoses "you're fine" 1000 times in a row will be 99% accurate and 0% useful.

Diagnose from the matrix

Spam classifier. Confusion matrix: 
              pred ham  pred spam
actual ham      900        50
actual spam      80       120
Compute: precision, recall for spam class. Which kind of error matters more, and why might users disagree?
SOLUTION
TP = 120; FP = 50; FN = 80; TN = 900

precision = TP / (TP + FP) = 120/170 = 0.71
recall    = TP / (TP + FN) = 120/200 = 0.60
F1        = 2·P·R / (P+R)  = 0.65
Critical: FP = real email in spam folder (loses your job). FN = spam in inbox (annoying). Different users want different tradeoffs. Always ask: which error costs more?

Metric 3 — precision, recall, F1

$$\text{precision} = \frac{TP}{TP+FP}$$

of what you flagged, how much was real.

$$\text{recall} = \frac{TP}{TP+FN}$$

of real positives, how many you caught.

$$F_1 = 2 \cdot \frac{P \cdot R}{P + R}$$

harmonic mean. Balanced single number.

from sklearn.metrics import classification_report

print(classification_report(y_test, y_pred))

#               precision  recall  f1   support
#       0          0.86     0.90  0.88     100
#       1          0.89     0.85  0.87     100
#
#  accuracy                       0.88     200

When in doubt, report F1. Single number. Tells you both sides.

Two models, which wins?

Same test set. Model A: accuracy 0.88, F1 0.45. Model B: accuracy 0.82, F1 0.71. Which would you ship for fraud detection? For predicting customer satisfaction (mostly happy)?
Think: High accuracy + low F1 = model trivially predicts majority class. F1 reflects minority-class performance.
DECISION
  • Fraud (imbalanced): ship Model B. Higher F1 = better at catching real fraud, even with lower accuracy.
  • Satisfaction (balanced-ish): Model A is fine; accuracy is honest here.
Critical: Metric depends on cost of errors and class balance. Pick the metric before you train, not after.

Cross-validation — trust the number

One train/test split is noisy. Different split → different score. K-fold CV averages over k splits.

test
train · train · train · train
train
test
train · train · train
… 5 folds total, each row used as test exactly once.
from sklearn.model_selection import cross_val_score

scores = cross_val_score(model, X, y, cv=5, scoring="f1")
scores.mean(), scores.std()

5 folds = 5 numbers. Mean ± std = honest estimate.

Can I trust 0.85?

One train_test_split gives accuracy 0.85. Your friend claims 0.91 using a different random_state. Who is right? How does 5-fold CV settle the argument?
SOLUTION
scores = cross_val_score(model, X, y, cv=5, scoring="accuracy")

scores.mean(), scores.std()
# e.g. 0.87 ± 0.03
# Both single-split numbers (0.85, 0.91) are inside ± 1 std. Noise.
Critical: Single split = lottery ticket. CV mean ± std = the real number. If two models differ by less than the std, the gap is probably noise.

Overfitting — the boss enemy

  • Train 99%. Test 70%. → Overfitting.
  • Model memorized noise instead of pattern.
Fixes:
  • More data.
  • Simpler model (lower max_depth).
  • Regularization (LogReg C smaller).
  • Cross-validate to detect.

Big train/test gap = warning siren.

Diagnose: overfit, underfit, or fine?

Three scenarios. Decide each:
  • ① train 0.99, test 0.62
  • ② train 0.71, test 0.69
  • ③ train 0.62, test 0.61
For each, recommend one concrete fix.
ANSWERS
  • ① Overfit. Big gap. Fix: reduce max_depth, add data, regularize.
  • ② Fine. Small gap, decent score. Maybe tune to push higher.
  • ③ Underfit. Even train is low → model too simple. Fix: stronger model, better features.
Critical: Always print both train and test scores. The number you see (test) only tells half the story.

Fix it — bias vs variance

Underfit (high bias)

  • Use stronger model (RF > LogReg).
  • Add features. Feature engineer.
  • Reduce regularization (LogReg C ↑).
  • Train longer / increase tree depth.

Overfit (high variance)

  • Get more data.
  • Simpler model (lower max_depth).
  • More regularization (LogReg C ↓).
  • Remove leaky / redundant features.
  • Use cross-validation to detect honestly.
Trap: if test > train — you almost certainly leaked. Test data crept into training. Re-check your split.

Day 3 pitfalls

  • Data leakage — fitting any transformer on test data. Fit on train, apply to test. Never the reverse.
  • Strings in X — sklearn errors. Encode first.
  • NaN in X — sklearn errors. Fill first.
  • No random_state — your "improvement" was just luck. Always seed.
  • Accuracy on imbalanced — lies. Use F1.
  • Score on train — meaningless. Score on test.

3 ways to handle imbalance

Dataset: 99% class 0, 1% class 1. Name three concrete strategies (with the sklearn knob) and the tradeoff of each.
STRATEGIES
  • ① class_weight="balanced" — sklearn re-weights loss. Free. First thing to try.
  • ② Threshold tuning — leave training alone, adjust cut after. Cheap, controllable.
  • ③ Resampling (imbalanced-learn): SMOTE (oversample minority) or undersample majority. Bigger change, can overfit.
Critical: Don't combine all three blindly. Start with class_weight + threshold. Resample only if those don't reach target recall.
