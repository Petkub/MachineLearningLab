The 5 lines that learn

  • Every PyTorch model trains via the same 5 lines. CNN, MLP, transformer — same shape.
  • Camp Day 3+ baselines all ship this exact pattern.
  • Your job: recognize it, then modify (change LR, add layer, swap loss).

Optimizer — update weights using gradients

import torch.optim as optim

optimizer = optim.Adam(model.parameters(), lr=0.001)
# or:
optimizer = optim.SGD(model.parameters(), lr=0.01, momentum=0.9)
optimizertypical lrwhen to use
Adam0.001safe default — works on most tasks
SGD + momentum0.01–0.1image classification, when carefully tuned
AdamW0.001transformers, weight decay handled correctly
  • First arg: model.parameters() — tells optimizer which tensors to update.
  • lr too big → loss explodes (NaN). lr too small → loss flat, no learning.
  • When unsure: Adam at lr=1e-3.

  • batch_size=64 typical. Bigger = faster, more RAM. Smaller = noisier gradients (sometimes helps).

Order matters. Skip any line → training fails or breaks silently. Memorize.

Step 1 — zero_grad() = erase whiteboard

PyTorch accumulates gradients by default. If you don't erase, every batch's gradient piles on top of the last.

no zero_grad
∂L/∂w = grad_1 + grad_2 + grad_3 + …
→ explodes, weights NaN
vs
with zero_grad
∂L/∂w = grad_this_batch
→ clean, training works
# forgot zero_grad — typical symptom:
loss after epoch 0: 2.3
loss after epoch 1: 847.5
loss after epoch 2: nan

Most common PyTorch bug. If your loss explodes, check this first.

Steps 2–4 — forward, loss, backward

# Step 2: forward — model runs, builds computation graph
output = model(x)
# PyTorch records every op (Linear, ReLU, ...) as it runs

# Step 3: loss — single scalar number
loss = criterion(output, y)
# this scalar is the "root" of the graph

# Step 4: backward — autograd traces graph backwards
loss.backward()
# PyTorch fills .grad attribute on every parameter
# after this: model.weight.grad has the gradient ∂loss/∂weight
  • forward = predict + record ops.
  • loss = scalar. Always one number per batch.
  • backward = chain rule, automated. You never write derivatives.

Trap: loss.backward() only works on a scalar. If loss is a tensor by accident, .mean() first.

Step 5 — optimizer.step() = move weights

optimizer.step()
# for every parameter p in model:
#   p.data = p.data - lr * p.grad   (SGD intuition)
# Adam adds momentum + per-parameter learning rate

Math (SGD): $w \leftarrow w - \eta \cdot \nabla_w L$.

  • Reads p.grad (filled by backward).
  • Writes p.data (the weight values).
  • Doesn't reset p.grad — that's zero_grad()'s job, called next iteration.
  • Cycle: zero → forward → loss → backward → step → zero → …

Full loop — epochs + batches + log

num_epochs = 5

for epoch in range(num_epochs):
    model.train()                    # enable training mode (dropout / batchnorm)
    running_loss = 0.0

    for x, y in train_loader:
        x, y = x.to(device), y.to(device)

        optimizer.zero_grad()         # 1
        output = model(x)             # 2
        loss = criterion(output, y)   # 3
        loss.backward()               # 4
        optimizer.step()              # 5

        running_loss += loss.item() * x.size(0)

    avg_loss = running_loss / len(train_loader.dataset)
    print(f'epoch {epoch}: loss={avg_loss:.4f}')
  • epoch = one full pass through the data. Typical: 5–50.
  • .item() on loss — converts 0-d tensor to Python float (else memory leak).
  • .to(device) on EVERY batch — model and data must be on same device.

Validation — score without learning

model.eval()                          # disable dropout / batchnorm running stats
correct = 0
total = 0

with torch.no_grad():                  # skip gradient tracking — saves memory + time
    for x, y in val_loader:
        x, y = x.to(device), y.to(device)
        output = model(x)
        preds = output.argmax(dim=1)
        correct += (preds == y).sum().item()
        total += y.size(0)

print(f'val acc: {correct / total:.4f}')
  • model.eval() + model.train() — toggle at start of each phase.
  • torch.no_grad() — skips autograd graph, ~2× faster validation.
  • argmax(dim=1) — pick highest-scoring class per row.

Loop order: train epoch → val epoch → log → repeat. Save best val checkpoint.
