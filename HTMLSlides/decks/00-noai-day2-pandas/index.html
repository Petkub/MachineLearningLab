loc vs iloc — which one?

Given a DataFrame with index [10, 20, 30, 40, 50] and columns ["a","b","c"]. Predict each result before running it:
① df.loc[20]   ② df.iloc[20]   ③ df.loc[10:30]   ④ df.iloc[10:30]
Think: loc = labels (inclusive end!). iloc = positions (exclusive end like Python). Indexes don't have to be 0,1,2.
SOLUTION
① df.loc[20]      → row with label 20 (the 2nd row)
② df.iloc[20]     → IndexError (only 5 rows!)
③ df.loc[10:30]   → rows labeled 10, 20, 30 (3 rows, inclusive)
④ df.iloc[10:30]  → empty DataFrame (positions 10..29 don't exist)
Critical: Most pandas bugs come from confusing these two. Read your own indices before slicing.

Boolean filtering

# one condition
df[df["age"] >= 18]

# multiple — use & | and parens (!!)
df[(df["age"] >= 18) & (df["city"] == "BKK")]

# is-in / not-in
df[df["city"].isin(["BKK", "CNX"])]
df[~df["name"].str.startswith("A")]

# between
df[df["age"].between(16, 18)]
Trap: Python and / or don't work. Use & / |. Parens mandatory around each condition.

Survivors in first class, age > 30

From Titanic, find female passengers in Pclass 1 who survived and were over 30. How many? Average fare they paid? Why does df[df.Pclass==1 and df.Age > 30] crash?
Think: Each condition = boolean column. Combine with & not and. Wrap each in parens — operator precedence will betray you otherwise.
SOLUTION
mask = (
    (df["Sex"]     == "female") &
    (df["Pclass"]  == 1) &
    (df["Survived"]== 1) &
    (df["Age"]     >  30)
)
group = df[mask]
n        = len(group)
avg_fare = group["Fare"].mean()
Why crash: Python's and wants a single truth value — but each side is an array. & works element-wise.

Fill Age — but how?

Titanic has 177 missing ages. You could fill with: (a) 0, (b) overall mean, (c) overall median, (d) group median by Pclass+Sex. Which is best, and why?
Think: (a) Lies — 0 implies infant. (b) Mean is skewed by outliers. (c) Median is robust but ignores context. (d) A 60-yr-old 1st-class woman ≠ 25-yr-old 3rd-class man.
SOLUTION
# simplest good answer: option (c) median
df["Age"] = df["Age"].fillna(df["Age"].median())

df["Age"].isna().sum()       # 0
Critical: Filling is a modeling decision, not a chore. Median is the safe default. The choice changes your score — document it.

merge — SQL JOIN for DataFrames

people = pd.DataFrame({"id": [1,2,3], "name": ["A","B","C"]})
scores = pd.DataFrame({"id": [1,2],     "score": [90, 85]})

people.merge(scores, on="id")                       # inner
people.merge(scores, on="id", how="left")           # keep all left
people.merge(scores, left_on="id", right_on="pid")
  • inner (default) — only matching keys.
  • left — keep all left rows. Missing right = NaN.
  • outer — union of keys. right — mirror of left.
  • concat = stack DataFrames vertically. Different beast.

Join scores to roster

Roster has 5 students with IDs [1,2,3,4,5]. Scores table has IDs [1,2,4,6]. After merge(how="left") on ID — how many rows? Which scores are NaN? When would how="inner" change your decisions?
Think: left = keep all roster, fill NaN where no score. inner = drop students missing scores. Pick by goal: "report on all students" vs "analyze only graded".
SOLUTION
left = roster.merge(scores, on="id", how="left")
# 5 rows. Students 3 and 5 → NaN for score.

inner = roster.merge(scores, on="id", how="inner")
# 3 rows (1, 2, 4). Student 6 from scores also dropped.
Critical: Wrong join silently loses rows. Always print(left.shape, before.shape) after a merge.

Read the heatmap

You run sns.heatmap(df.corr()). You see Fare ↔ Pclass = -0.55 and SibSp ↔ Parch = +0.41. Interpret each. Which pair signals possible multicollinearity? Which signals a strong predictor?
Think: Negative correlation = inverse. Fare high → Pclass low (Pclass 1 = upper class). High |corr| between features → redundancy. Corr between feature and target = potential signal.
INTERPRETATION
  • Fare ↔ Pclass = −0.55 — same information twice (cheap ticket = low class). Drop one if linear model gets confused.
  • SibSp ↔ Parch = +0.41 — bigger families travel together. Combine into family_size = SibSp + Parch + 1.
  • Sex ↔ Survived (if you encode) — biggest single predictor.
Critical: Heatmap doesn't tell you the answer — it asks you better questions.

EDA workflow on a new dataset

  1. df.info() — what dtypes? how many NaN?
  2. df.describe() — sane numeric ranges?
  3. df["target"].value_counts() — class balance?
  4. sns.heatmap(df.corr()) — what predicts what?
  5. sns.pairplot(df, hue="target") — separable?
  6. Pick one feature, sns.boxplot against target.
  7. Write down hypothesis. Then open sklearn.

EDA = 30 min. Modeling = 5 min if EDA was honest.

concat or merge?

① Train data + test data: same columns, different rows. Combine them.
② Customer table + their orders: same customer ID, different columns. Combine them.
ANSWER
① pd.concat([train, test])              # stack rows
② customers.merge(orders, on="id")      # join by key
Critical: concat = vertical stack (same schema). merge = horizontal join (same keys). Pick by axis of growth.

Day 2 pitfalls

  • SettingWithCopyWarning — chained df[x][y] = .... Use df.loc[x, y] = ....
  • inplace=True — confusing. Just reassign: df = df.dropna().
  • String columns = sklearn can't eat them. Drop or encode.
  • NaN in target — silent disaster. Always check df["y"].isna().sum().
  • apply for everything — slow. Vectorize first.
