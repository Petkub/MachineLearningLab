The List

Many things, in order.
Numbered from zero.

Making a list

playlist = ["Levitating", "Shape of You", "Viva La Vida"]
scores   = [82, 91, 67, 75]
empty    = []                       # a list with nothing in it yet
mixed    = ["Ann", 82, True]           # allowed, but rarely a good idea
  • Square brackets [ ]. Items separated by commas.
  • The items are called elements. They stay in the order you wrote them.
  • len(playlist) tells you how many: 3.

Order is the whole point of a list. Song 1 plays before song 2.

Index — counting starts at ZERO

playlist = ["Levitating", "Shape of You", "Viva La Vida", "Lose Yourself"]
"Levitating"

playlist[2]   # "Viva La Vida"
playlist[4]   # IndexError: list index out of range
The #1 beginner bug. 4 songs means indexes 0 1 2 3. The last index is len(playlist) - 1, never len(playlist).

Negative index — counting from the back

"Levitating"

"Shape of You"

There is no -0. Back-counting starts at -1, because 0 is already taken by the front.

Slicing — take a piece of the list

nums = [10, 20, 30, 40, 50]

nums[1:4]    # [20, 30, 40]   ← from 1, STOP BEFORE 4
nums[:3]     # [10, 20, 30]   ← from the start
nums[2:]     # [30, 40, 50]   ← to the end
nums[-2:]    # [40, 50]       ← last two
Read it as: "start here, stop before there." nums[1:4] gives you 4 − 1 = 3 items. That subtraction always works.
Slice never crashes. nums[2:99] is fine — it just stops at the end. But nums[99] raises IndexError. One bracket pair, two very different behaviours.

Changing an item

order = ["pad thai", "green curry", "mango sticky rice"]

order[1] = "tom yum"
print(order)   # ['pad thai', 'tom yum', 'mango sticky rice']
  • Lists are mutable — you can change them after they are made.
  • Same bracket you used to read (order[1]), now on the left of = to write.
  • The list keeps its identity. It is the same list, edited — not a new one.

Read: x = order[1]. Write: order[1] = x. Bracket on the left means change.

Growing a list — append & insert

APPEND · ADD TO THE END

playlist = ["Levitating", "Shape of You"]
playlist.append("Viva La Vida")

# ['Levitating', 'Shape of You',
#  'Viva La Vida']

INSERT · ADD AT A POSITION

playlist.insert(0, "Intro")

# ['Intro', 'Levitating',
#  'Shape of You', 'Viva La Vida']
Do not write playlist = playlist.append("X"). append changes the list and returns None — you would throw your playlist away and keep nothing. Just write playlist.append("X") on its own line.

Shrinking a list — remove & pop

REMOVE · BY VALUE

playlist.remove("Intro")
# deletes the FIRST "Intro" it finds
# ValueError if it is not there

POP · BY POSITION

last = playlist.pop()      # takes the last
first = playlist.pop(0)    # takes index 0
# pop GIVES YOU BACK what it removed
Which one? You know what to delete → remove. You know where it is, or you want the item back → pop.

del playlist[2] also works — deletes by position, gives nothing back.

Two questions every list can answer

scores = [82, 91, 67, 75]

len(scores)        # 4      ← how many?
91 in scores      # True   ← is it there?
50 in scores      # False
"pad thai" in order   # works for strings too
  • in gives back True / False — perfect inside an if.
  • Also handy: sum(scores), max(scores), min(scores), scores.count(91), scores.index(67).
if "tom yum" in order:
    print("already ordered!")

Looping over a list

THE NORMAL WAY

for song in playlist:
    print(song)

# Levitating
# Shape of You
# Viva La Vida

song is a name you choose. It becomes each item, one at a time.

WHEN YOU NEED THE POSITION

for i, song in enumerate(playlist):
    print(i, song)

# 0 Levitating
# 1 Shape of You
# 2 Viva La Vida

enumerate hands you the index and the item.

Loop first, count second. Reach for enumerate only when you actually need the number.

Loop + build: the pattern you will reuse forever

scores = [82, 91, 67, 75]

passed = []                     # 1. start empty
for s in scores:              # 2. walk the input
    if s >= 70:                # 3. test
        passed.append(s)        # 4. keep the good ones

print(passed)                   # [82, 91, 75]
Empty → loop → test → append. Filtering, counting, totalling, searching — they are all this same four-line skeleton with a different middle.

Never append to the list you are looping over. The loop will never end.

Sorting

scores = [82, 91, 67, 75]

scores.sort()                # CHANGES scores → [67, 75, 82, 91]
scores.sort(reverse=True)   # [91, 82, 75, 67]
scores.reverse()             # flips whatever order it is in now

ranked = sorted(scores)      # NEW list, original untouched

.sort()

Changes the list in place. Returns None.

sorted(...)

Leaves the list alone. Returns a new sorted list.

Strings sort alphabetically — but uppercase comes before lowercase: "Zoe" < "ann".

Fix the playlist

playlist = ["Intro", "Levitating", "Shape of You", "Outro"]
Write the code to: (1) print the last song without using the number 3   (2) delete "Intro"   (3) add "Encore" at the very end   (4) print how many songs are left.
ANSWER
print(playlist[-1])          # "Outro" — works at any length
playlist.remove("Intro")     # or playlist.pop(0)
playlist.append("Encore")
print(len(playlist))         # 4
Why -1 and not 3? Because tomorrow the playlist has 40 songs and playlist[3] is suddenly the wrong song. -1 is never wrong.

Count the high scores

scores = [55, 82, 91, 67, 75, 48, 88]
Print how many scores are 80 or above, and the average of the whole list. Use a loop for the first one.
ANSWER
count = 0
for s in scores:
    if s >= 80:
        count = count + 1
print(count)                        # 3
print(sum(scores) / len(scores))    # 72.28...
Same skeleton as before — start at zero, walk, test, update. Only "keep it" became "count it".

Biggest without max()

temps = [28, 31, 27, 35, 30]
Find the hottest temperature using a loop. You may not use max().
Then: also print which day it was (day 0, day 1, ...).
ANSWER
best = temps[0]                      # start with a REAL value, not 0
best_day = 0
for i, t in enumerate(temps):
    if t > best:
        best = t
        best_day = i
print(best, "on day", best_day)     # 35 on day 3
Why start at temps[0] and not 0? Try it with [-5, -9, -3]. Starting from 0 gives you 0 — a temperature that is not even in the list.

Clean the sign-up sheet

signups = ["ann", "ben", "ann", "cat", "ben", "ann"]
Build unique — each name once, keeping the order they first signed up. Then print how many people actually signed up.
Before you code: you already know the skeleton. Empty → loop → test → append. The only new part is the test. What is it?
ANSWER
unique = []
for name in signups:
    if name not in unique:      # the test: have I seen it already?
        unique.append(name)
print(unique)                # ['ann', 'ben', 'cat']
print(len(unique))           # 3
Careful with in: the test is against unique, the list you are building — not signups. Test against signups and you keep nothing.

PART TWO · 40 MIN

The Dictionary

Look things up by name.
No counting required.

Where the list falls apart

A menu. Two lists, kept side by side:

items  = ["pad thai", "green curry", "mango sticky rice"]
prices = [60, 80, 45]

# How much is green curry?
i = items.index("green curry")   # find WHERE it is... 1
print(prices[i])                # ...then look in the other list
  • Two steps for one question.
  • If you sort prices and forget items, every price is now wrong and nothing crashes.
  • Add a dish to one list only → silently broken forever.

Two lists that must stay lined up = a bug waiting to happen. Use a dictionary.

Making a dictionary

prices = {"pad thai": 60, "green curry": 80, "mango sticky rice": 45}
"pad thai"
60
"green curry"
80
"mango sticky rice"
45
  • Curly braces { }. Each entry is key : value.
  • The key is the label you search by. The value is what you get back.
  • Keys must be unique — one price per dish. Values can repeat freely.

List = "give me #2". Dictionary = "give me green curry".

Looking up, adding, changing

prices = {"pad thai": 60, "green curry": 80}

print(prices["pad thai"])          # 60      ← LOOK UP

prices["tom yum"] = 70            # key is new  → ADDS it
prices["pad thai"] = 65            # key exists  → OVERWRITES it

del prices["green curry"]          # DELETE the whole entry
Same line, two meanings. d[k] = v adds if the key is new, replaces if it is not. Python never asks "are you sure?" — a typo'd key quietly creates a second entry.

Square brackets again — but a name goes inside, not a number.

Play with it — lookup machine

Type a dish name, or click a card above.
Try a key that does not exist — like "pizza" — in each of the four modes.

The missing key — KeyError vs .get

BRACKETS · CRASHES

prices["pizza"]
# KeyError: 'pizza'
# program stops. dead.

.get · STAYS ALIVE

prices.get("pizza")      # None
prices.get("pizza", 0)   # 0
# second argument = fallback
if "pizza" in prices:        # `in` checks the KEYS, never the values
    print(prices["pizza"])
else:
    print("not on the menu")
80 in prices is False even though 80 is a price. in only ever looks at keys.

Looping over a dictionary

prices = {"pad thai": 60, "green curry": 80, "mango sticky rice": 45}

KEYS

for dish in prices:
    print(dish)

# pad thai
# green curry
# mango sticky rice

VALUES

for p in prices.values():
    print(p)

# 60
# 80
# 45

BOTH · USE THIS ONE

for dish, p in prices.items():
    print(dish, p)

# pad thai 60
# green curry 80
# mango sticky rice 45

Looping a dict plainly gives you the keys, not the values. Want both? .items().

Counting with a dictionary

The classic use: count how many of each thing.

votes = ["pizza", "sushi", "pizza", "tacos", "pizza", "sushi"]

tally = {}                               # 1. start empty
for v in votes:                        # 2. walk the list
    tally[v] = tally.get(v, 0) + 1      # 3. old count (or 0) + 1

print(tally)   # {'pizza': 3, 'sushi': 2, 'tacos': 1}
Line 3 is the whole trick. .get(v, 0) means "how many so far — and if I have never seen this one, call it zero." Without it, the first vote for each item is a KeyError.

List → dictionary is how raw data becomes a summary.

List or dictionary? Decide in one question

USE A LIST WHEN...

  • the order matters (playlist, queue, steps)
  • you have many of the same kind of thing
  • you will loop over all of it
  • you find things by position

USE A DICTIONARY WHEN...

  • each item has a name / id
  • you look things up by that name
  • you are describing one thing's properties
  • you are counting or summarising
Ask yourself: "when I need one item back, what will I know about it — where it is, or what it is called?" Where → list. Called → dictionary.
Songs to play in orderlist Country → capitaldict
One song's title/artist/yeardict Every test score in classlist

Build the phonebook

capitals = {"Thailand": "Bangkok", "Japan": "Tokyo", "France": "Paris"}
(1) Add Korea → Seoul.   (2) Print France's capital.   (3) Print the capital of Brazil without crashing.   (4) Print every line as Thailand -> Bangkok.
ANSWER
capitals["Korea"] = "Seoul"
print(capitals["France"])                      # Paris
print(capitals.get("Brazil", "unknown"))       # unknown  — no crash
for country, city in capitals.items():
    print(country, "->", city)
Why .get in (3)? Real data always has holes. A program that dies on the first missing key is useless the moment it meets the real world.

Count the letters

word = "banana"
Count how many times each letter appears. Expected output: {'b': 1, 'a': 3, 'n': 2}.
Hint: for ch in word: walks a string one letter at a time — same as a list.
ANSWER
counts = {}
for ch in word:
    counts[ch] = counts.get(ch, 0) + 1
print(counts)      # {'b': 1, 'a': 3, 'n': 2}
Identical to the vote counter. Different data, same three lines. That is what a pattern means — learn it once, use it everywhere.

Update the menu

menu    = {"pad thai": 60, "green curry": 80}
new     = {"green curry": 85, "tom yum": 70}
Apply new to menu: prices that changed get updated, dishes that are new get added. Use a loop — then print the total price of the whole menu.
ANSWER
for dish, price in new.items():
    menu[dish] = price          # one line does BOTH jobs

print(menu)                     # {'pad thai': 60, 'green curry': 85, 'tom yum': 70}
print(sum(menu.values()))       # 215
You did not need an if. menu[dish] = price already means "add it, or replace it". That is exactly why dictionaries are pleasant to update and two parallel lists are not.

Longest word wins

sentence = "the quick brown fox jumps"
Build lengths = {word: how many letters}, then print the longest word.
Hint: sentence.split() gives you ['the', 'quick', ...].
ANSWER
lengths = {}
for w in sentence.split():
    lengths[w] = len(w)

longest = ""
for w, n in lengths.items():
    if n > len(longest):
        longest = w
print(lengths)
print(longest)                  # quick
"quick", "brown" and "jumps" are all 5 letters. Your code returned one of them — which? Whichever came first, because > only replaces on a strictly bigger value. Swap it to >= and you get the last one instead.

List of Dictionaries

Many records, each with many fields.
The shape real data actually has.

The shape everything real has

A class roster is many students (list), and each student has fields (dictionary):

students = [
    {"name": "Ann", "score": 82, "club": "robotics"},
    {"name": "Ben", "score": 91, "club": "music"},
    {"name": "Cat", "score": 67, "club": "robotics"},
]
  • Outer [ ] → a list. Its items happen to be dictionaries.
  • Every dictionary uses the same keys. That is what makes it a table.
  • This is exactly how a spreadsheet, a database row, and a JSON API all look.

Rows = the list. Columns = the keys.

Reaching in — index first, then key

students[0]                    # {'name': 'Ann', 'score': 82, 'club': 'robotics'}
students[0]["name"]            # 'Ann'
students[1]["score"]           # 91
students[-1]["club"]           # 'robotics'
Read left to right. students[1] picks the row → you now hold one dictionary → ["score"] picks the column. Two brackets, two different jobs. 
students[0]["score"] = 85       # editing works the same way
students.append({"name": "Dan", "score": 74, "club": "art"})
Number in the first bracket, name in the second. students["Ann"] is a TypeError — the outer thing is a list; lists know nothing about names.

Play with it — record drill-down

CLICK ANY CELL · SEE THE CODE THAT REACHES IT
Click a cell in the table.
Click the blue index column to grab a whole record (a dictionary) instead of one field.

Looping over records

for s in students:
    print(s["name"], s["score"])

# Ann 82
# Ben 91
# Cat 67
Each turn of the loop, s is one whole dictionary. So inside the loop you stop thinking about the list entirely — you just have "a student", and you ask it for its fields.

Name the loop variable after one of the things: for s in students, for song in playlist. Never for x in y.

Filtering records

robotics = []                       # empty
for s in students:                 # loop
    if s["club"] == "robotics":     # test — reach into the record
        robotics.append(s)          # keep the WHOLE record

for s in robotics:
    print(s["name"])                # Ann, Cat
The same four-line skeleton from Part One. Empty → loop → test → append. The only change: the test reaches inside a dictionary, and you keep the whole record, not just a number.

Keep the whole record, not s["name"] — later you will want the other fields too.

Read the roster

Using the same students list — (1) print Ben's club without looking at index 1 (search for him).   (2) print the average score of the class.
ANSWER
for s in students:               # (1) search by field
    if s["name"] == "Ben":
        print(s["club"])           # music

total = 0                          # (2) add up, then divide
for s in students:
    total = total + s["score"]
print(total / len(students))       # 80.0
Notice what (1) really is: a list search by a name. If you do that a lot, that is Python telling you the outer container maybe wanted to be a dictionary keyed by name.

Who is in which club?

Using the roster (Ann/robotics, Ben/music, Cat/robotics, Dan/art, Eve/music) — build members = {club: [names]}, so that members["robotics"] gives ['Ann', 'Cat'].
This is the counting pattern with one change. Instead of a number going up by one, the value is a list you append a name to. What should the missing-key fallback be?
ANSWER
members = {}
for s in students:
    club = s["club"]
    if club not in members:
        members[club] = []            # first time: start an empty list
    members[club].append(s["name"])

# shorter, same thing:
# members.setdefault(club, []).append(s["name"])
print(members)   # {'robotics': ['Ann','Cat'], 'music': ['Ben','Eve'], 'art': ['Dan']}
Do not write members.get(club, []).append(name). That appends to a throwaway empty list when the key is missing — nothing is saved and nothing errors. A silent bug, the worst kind.

Grade bump

The teacher adds 5 points to everyone in robotics (capped at 100), then a new student joins: Gus, 79, art.
Write both changes, then print every name with its final score.
ANSWER
for s in students:
    if s["club"] == "robotics":
        s["score"] = min(s["score"] + 5, 100)

students.append({"name": "Gus", "score": 79, "club": "art"})

for s in students:
    print(s["name"], s["score"])
Editing inside a loop is fine — s is the real record, not a copy, so s["score"] = ... changes the roster. But appending to a list while looping over it is not: the loop would keep finding the items you just added, forever. That is why the append is outside.

Mini-project — the data

students = [
    {"name": "Ann",  "score": 82, "club": "robotics"},
    {"name": "Ben",  "score": 91, "club": "music"},
    {"name": "Cat",  "score": 67, "club": "robotics"},
    {"name": "Dan",  "score": 74, "club": "art"},

]
Q1. Who scored highest?    Q2. How many students in each club?    Q3. Add a new student, then print the class average.

Try it yourself first. Next three slides are the answers, one at a time.

Q1 — who scored highest?

best = students[0]                 # assume the first is the winner

for s in students:
    if s["score"] > best["score"]:   # found someone better?
        best = s                    # they are the new champion

print(best["name"], best["score"])   # Ben 91
Why start at students[0] and not 0? Because best holds a whole record, not a number — you need the name at the end, not just the score. Starting from the first real student also works when scores are negative.
Empty list? students[0] is an IndexError. Real programs check if len(students) > 0: first.

Q2 — how many in each club?

by_club = {}                                       # list → summary dict

for s in students:
    club = s["club"]
    by_club[club] = by_club.get(club, 0) + 1

print(by_club)   # {'robotics': 2, 'music': 2, 'art': 1}
You have written this exact loop three times today — votes, letters, now clubs. .get(key, 0) + 1 is the counting pattern. It never changes. 
# want the NAMES in each club, not just the count?
for s in students:
    by_club.setdefault(s["club"], []).append(s["name"])
# {'robotics': ['Ann', 'Cat'], 'music': ['Ben', 'Eve'], 'art': ['Dan']}

Q3 — add a student, print the average

students.append({"name": "Fay", "score": 95, "club": "art"})

total = 0
for s in students:
    total = total + s["score"]

average = total / len(students)
print("class size:", len(students))   # 6
print("average:", round(average, 1))  # 82.8
Everything today, in nine lines: a list that grows (append), records with named fields (s["score"]), a loop that accumulates, and len() to size it.

Rerun it after adding Fay — the average changes by itself. That is why you never hard-code 5.

The five things to remember

  • Counting starts at 0. The last index is len(xs) - 1, or just -1.
  • List = by position. Dictionary = by name. Pick by asking what you will know when you look something up.
  • Empty → loop → test → append. Filtering, counting, totalling — all the same skeleton.
  • .get(k, 0) + 1 counts anything, ever.
  • Real data is a list of dictionaries. Rows are the list, columns are the keys.
