NOAI Teacher Guide

How to teach the 3-day track + exercises
Stage 2 pre-camp · survival-focused

This is the instructor's playbook for the 3 NOAI days on the website. For each day you get: what the day is for, how to drive the slide deck, how to run the in-class exercise notebook, how to assign + grade the homework, and a checkpoint you must clear before moving on. Read the philosophy first — it changes how you teach every slide.

1 · Teaching philosophy

The goal is not to make ML experts. The goal is one sentence:

The whole point Make the student survive the official camp — keep up with mentors, read a baseline notebook without panic, and change code without breaking it. Not: win the competition. Not: understand backprop math.

Five rules. They override your instinct to "explain properly":

  • 80/20. Teach the 20% of syntax that covers 80% of camp tasks. The decks already cut to this — don't add the parts you miss.
  • Pattern over theory. A reusable code template beats a derivation. Students should leave with patterns memorized, not proofs.
  • Run first, understand later. Make code run, see output, then explain. Never explain a concept the student hasn't seen execute.
  • Live-code, type don't paste. Typing slows you to student speed and shows them debugging in real time — the single most useful skill.
  • Make mistakes on purpose. Forget plt.show(). Misspell a column. Recover visibly. They learn the fix by watching the fix.
Pacing rule Every ~10 minutes, stop and invite a question. If nobody runs the code, you went too fast. A confused-but-running room beats a quiet-and-lost room.
2 · How slides + notebooks fit together

Each day has three assets. Use them in this order:

AssetWhenHow to use it
Slide deck
in class		 First ~50–60 min You drive it. Every "problem" slide and widget = stop, let students try, then reveal. Don't read slides aloud — code them live alongside.
Exercise notebook
in class		 Last ~30–40 min Students drive. You walk the room. Numbered problems + a final "find the bugs" problem. Solutions are at the bottom — tell them not to scroll yet.
Homework notebook
after class		 Before next day Less guidance, hints hidden, ends in a capstone. Review the capstone at the start of the next day (5 min).
Non-negotiable Do not skip the exercise notebook to "finish the slides". A finished deck with no hands-on time means zero retention. If short on time, cut slides, never the notebook.
3 · Day 1 — NumPy

Day 1 — NumPy: arrays without loops

Survival outcome Student sees arr[:, 1:] or arr.mean(axis=0) in a camp notebook and reads it correctly — "all rows, columns from 1 on" / "mean of each column". They stop reaching for a for loop.

Deck — 13 slides, the spine

Arc: list vs array → why arrays → create → shape/reshape → index/slice → vectorized math → broadcasting → boolean masks → image is an array. Slides to slow down on:

  • "Why arrays?" — run the Python-list-loop version next to the NumPy one. Speed difference is the whole motivation. Don't rush past it.
  • "Shape & reshape" + "Image as numbers" — shape confusion is the #1 camp killer. Make them say the shape out loud before every operation.
  • "Broadcasting" + "Normalize each column" — the hardest idea of the day. Draw the stretch on the board. Expect blank faces; the exercise fixes it, not the slide.
  • "Boolean masks — filtering" — bridge to Day 2. Same idea returns as df[df['x'] > 5] tomorrow; say so explicitly.

"Problem" slides (Temperature buffer, Even-indexed students, Celsius→Fahrenheit, Find the outliers, Best student/subject) — stop, 60–90 s, let them try, then reveal.

Concepts + code — what to actually say while typing

1 · List vs array — the motivation. Type both. Run both. Let the speed gap land before you say a word.

# Python list — manual loop
nums = [1, 2, 3, 4]
doubled = []
for n in nums:
    doubled.append(n * 2)

# NumPy — no loop, runs in C
import numpy as np
arr = np.array([1, 2, 3, 4])
doubled = arr * 2          # [2 4 6 8]

Say: "The loop is you doing the work. arr * 2 is NumPy doing the loop for you, in C, 100× faster. At camp, datasets are huge — loops time out, NumPy doesn't."

2 · Shape is everything. Every camp bug is a shape bug. Drill the habit of printing .shape before any operation.

a = np.arange(12)        # [0 1 2 ... 11]
a.shape                  # (12,)   — 12 numbers, 1 dimension
b = a.reshape(3, 4)      # 3 rows, 4 cols
b.shape                  # (3, 4)
# reshape(3, 5) -> ERROR: 12 != 15. Total elements must match.

Say: "(3, 4) reads as rows, columns. Reshape only rearranges the same numbers — the total never changes. When sklearn or PyTorch screams later, it is almost always two shapes that don't line up."

3 · Slicing — read it like a sentence.

m = np.array([[10, 11, 12],
              [20, 21, 22],
              [30, 31, 32]])
m[0]        # first row          -> [10 11 12]
m[:, 0]     # every row, col 0   -> [10 20 30]
m[1:, 1:]   # rows from 1, cols from 1 -> [[21 22],[31 32]]

Say: "Comma splits dimensions: [rows, columns]. Colon alone means 'all of them'. Read m[:, 0] out loud as 'all rows, column zero'. Make the students say it before they run it."

4 · Vectorized math + broadcasting — the hard one. Draw the stretch on the board.

temps_c = np.array([0, 20, 37, 100])
temps_f = temps_c * 9/5 + 32        # whole array at once

scores = np.array([[80, 90],
                   [60, 70]])
col_mean = scores.mean(axis=0)      # [70. 80.]  (per column)
normalized = scores - col_mean      # shape (2,2) - shape (2,) -> broadcast

Say: "axis=0 = the dimension that disappears — collapse the rows, one number per column. Broadcasting = NumPy stretches the small array to fit the big one so the shapes match. Expect confused faces here; the exercise fixes it, not this slide."

5 · Boolean mask — the bridge to tomorrow.

ages = np.array([12, 17, 25, 9, 40])
ages > 18                 # [False False True False True]
ages[ages > 18]           # [25 40]  — keep where True

Say: "A condition makes a True/False array. Index with it to keep only the True rows. Tomorrow this exact idea returns as df[df['age'] > 18] in Pandas. Say that out loud — it pays off Day 2."

6 · np.where + build the matrix — straight into Day 3.

ages = np.array([12, 17, 25, 9, 40])
np.where(ages >= 18, 1, 0)        # [0 0 1 0 1]  vectorized if/else

age = np.array([17, 16, 18]); height = np.array([170, 165, 180])
X = np.column_stack([age, height])    # shape (3, 2): rows=samples, cols=features
X_train, X_test = X[:2], X[2:]        # split = slice rows

Say: "Mask picks rows; np.where transforms them — that's how you turn Sex into 0/1 for a model. column_stack glues feature arrays into one X; slicing splits it. Day 3, train_test_split(X, y) is literally this — they'll recognize it instead of fearing it."

4 · Day 2 — Pandas + Matplotlib + Seaborn

Day 2 — Pandas: any CSV → clean → look

Survival outcome Hand the student an unknown CSV. In 60 seconds they run head / info / describe / isnull().sum(), filter rows, group, and plot one chart — without asking what to do first.

Deck — 19 slides, the biggest day

Real datasets: Penguins (clean) and Titanic (messy, missing values). Arc: why pandas → DataFrame → read CSV → first-60-seconds ritual → select → filter → new columns / feature engineering → missing values → groupby → sort/unique/top-N.

  • "First 60 seconds with a new CSV" — the most important slide of the day. Make it a recited ritual: head → info → describe → isnull().sum(). They'll use this on race day before touching anything.
  • "Fill Age — but how?" — teach the decision, not just fillna. Mean vs median vs drop, and why it matters. Camp datasets are always messy.
  • "Feature engineering — Title from Name" — first taste of "make a feature". Don't over-explain; show it works, move on.
  • "Who actually survived?" / "Class summary, one shot" — groupby is the payoff slide. Connect it back to Day 1 aggregations.
Watch df[df['x'] = 5] (single =) will be written by someone. It's a syntax error. Show the correct == version more than once. Also: someone will forget plt.show() — let a blank cell happen, then fix it.

Concepts + code — what to actually say while typing

1 · DataFrame = a spreadsheet Python can compute on. Open Penguins live.

import seaborn as sns
df = sns.load_dataset('penguins')   # real data, has missing values
df.shape                            # (344, 7)  rows, columns

Say: "Rows = records. Columns = features. .shape is the same idea as NumPy yesterday — always check it first."

2 · The 60-second ritual. The single most important habit of camp. Make them recite the four lines.

df.head()              # what does a row look like?
df.info()              # column types + how many non-null
df.describe()          # min/max/mean of numeric columns
df.isnull().sum()      # how many missing, per column

Say: "On race day you get a CSV you've never seen. Before any modelling, you run these four. info() and isnull().sum() together tell you exactly what's broken. This ritual buys you the whole task."

3 · Select & filter — boolean mask, Pandas edition. Tie back to Day 1.

df['species']                          # one column
df[['species', 'body_mass_g']]         # several columns (double brackets!)
df[df['body_mass_g'] > 4000]           # filter rows by condition
df[(df['sex'] == 'Female') & (df['island'] == 'Dream')]   # & not 'and'

Say: "Yesterday: arr[arr > 5]. Today: same idea, df[df['x'] > 5]. Two conditions use & and each side needs parentheses. Single = is a crash — it's always written by someone."

4 · Missing values — teach the decision, not the function.

df['body_mass_g'].isnull().sum()       # how bad is it?
df['body_mass_g'].fillna(df['body_mass_g'].median())   # median: robust to outliers
df.dropna()                            # drop rows — only if few are missing

Say: "Mean is dragged by outliers; median isn't — for body mass, use median. Drop rows only when missing count is tiny. There is no default — you decide and you justify it. Camp datasets are always messy on purpose."

5 · Groupby — the payoff. Same as Day 1 aggregation, by category.

df.groupby('species')['body_mass_g'].mean()
# Titanic: who survived?
titanic.groupby('class')['survived'].mean()   # survival rate per class

Say: "Split by a column, compute per group. groupby('class')['survived'].mean() reads as 'survival rate for each class'. This one line answers most EDA questions a mentor will ask you."

6 · Plot — goal is 'a chart appears', not beauty.

import matplotlib.pyplot as plt
df['body_mass_g'].plot.hist(bins=20)
plt.show()                             # FORGET THIS = blank. On purpose, once.

Say: "One distribution → histogram. Two numbers → scatter. A category count → bar. Always end with plt.show(). Don't style anything — at camp you plot to understand, not to present."

5 · Day 3 — scikit-learn

Day 3 — scikit-learn: one API, every model

Survival outcome Student reads any sklearn notebook and predicts what each block does, and can swap LogisticRegression for RandomForestClassifier with the rest of the code unchanged.

Deck — 24 slides, biggest payoff

Real datasets: Iris + Titanic-like. The deck's spine is the 5-step pipeline mantra — make them recite it:

1. LOAD     →  pd.read_csv()
2. SPLIT    →  train_test_split(X, y)
3. FIT      →  model.fit(X_train, y_train)
4. PREDICT  →  preds = model.predict(X_test)
5. EVALUATE →  accuracy_score(y_test, preds)
  • "sklearn — one API for every model" — the thesis of the whole day. Same .fit/.predict on every model. If they get only this, the day worked.
  • "Why split?" + "The imbalanced split" — explain conceptually (estimate generalization), no math. The imbalanced-split slide shows why random_state / stratify matters.
  • "Why sklearn screams" — the shape/NaN errors they'll actually hit at camp. This is survival gold; spend real time here.
  • "Model 1 LogReg" → "Model 2 Random Forest" — teach by diffing: change two lines, same pipeline, better score. That's the entire mental model.
  • "Decision boundaries — interactive" — let them play 2–3 min. Intuition for what a model "learns" without a single equation.

Concepts + code — what to actually say while typing

1 · Supervised ML in one breath. No math.

Say: "We have X (features, what we know) and y (label, what we want to predict). fit = the model looks at X and y and finds a pattern. predict = apply that pattern to new X. That's all 'learning' is at this level."

2 · The full pipeline — type it once, top to bottom. This is the day.

from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

X, y = load_iris(return_X_y=True)                       # 1. LOAD
X_tr, X_te, y_tr, y_te = train_test_split(              # 2. SPLIT
        X, y, test_size=0.2, random_state=42)
model = LogisticRegression(max_iter=200)
model.fit(X_tr, y_tr)                                   # 3. FIT
preds = model.predict(X_te)                             # 4. PREDICT
print(accuracy_score(y_te, preds))                      # 5. EVALUATE

Say: "Five steps, every time, every task. Make them point at each line and name the step. They should be able to write this skeleton from memory by the end of the day."

3 · Why split — conceptual, no formula.

Say: "If you test on the data you trained on, the model just memorized — score means nothing. Hold out 20% it never saw. random_state=42 makes the split repeatable so your score isn't luck. The 'imbalanced split' slide shows why this matters."

4 · One API for every model — teach by diffing. Change two lines, rerun.

from sklearn.ensemble import RandomForestClassifier
model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_tr, y_tr)                  # SAME line
preds = model.predict(X_te)            # SAME line

Say: "Only the import and the class name changed. .fit / .predict are identical. This is the single most useful fact for camp — to try a different model you swap two lines, nothing else."

5 · Read the output — not just the accuracy number.

from sklearn.metrics import classification_report
print(classification_report(y_te, preds))

Say: "Precision = 'when it said class A, was it right?'. Recall = 'of all real class A, how many did it catch?'. On imbalanced data, accuracy lies — this table tells the truth. You don't compute these, you read them."

6 · Cross-validation — 'one split can lie'. Concept only.

from sklearn.model_selection import cross_val_score
cross_val_score(model, X, y, cv=5).mean()   # 5 splits, average score

Say: "One split might be a lucky or unlucky 20%. CV does it 5 times and averages — a score you can trust. Don't go deep; just the why."

7 · The integration task = the real exam. Day 2 cleaning + Day 3 pipeline on Titanic. If a student does this unaided, they survive camp. Say that to them.

6 · Mistakes to catch on sight

Memorize these. When you see one while walking the room, fix it on the spot — these are exactly the errors that lose camp time.

MistakeDayFix / what to say
arr.reshape with wrong element count1"Total elements must match. Count them."
Loop where vectorized math works1Show the one-liner. "NumPy does the loop for you."
axis off by one in aggregations1,3"axis = the dimension that disappears."
df[df['x'] = 5] single =2Syntax error. Use ==. Show it twice.
Forgot plt.show()2Let the blank happen once, then add it.
Filling missing values blindly2"Mean or median? Why?" Make them justify.
No train/test split3Show with-split vs without side by side.
NaN passed into .fit()3Read the last line of the traceback, not the first.
Changing many things, score moved, can't tell why3"One change, then re-run. Always."
Debugging mantra to drill Teach this on Day 1, repeat every day: read the LAST line of the error, then print(df.head()) / print(arr.shape) / print(len(x)) at every step. This single habit is worth more than any model.
7 · Logistics & pre-camp setup
  • One week before: send the Colab links. Colab is recommended over local installs — it removes every setup failure. Verify each student can open and run one cell before Day 1.
  • Each day: deck open on the projector, exercise notebook link in chat, homework link given at the end.
  • Start of each day: 5 minutes reviewing one student's previous-day capstone on the projector. This is the highest-value review you can do.
  • Time budget per day (~90 min): deck 50–60 min · exercise notebook 30–40 min · homework assigned, not done in class.
  • If you run short: cut deck slides (the "problem" slides can be self-study), never cut hands-on notebook time.
If you remember one thing A student who can do the Day 3 Titanic end-to-end capstone unaided will survive the camp. Everything in these 3 days exists to get them there. Optimize the room toward that, not toward finishing slides.
